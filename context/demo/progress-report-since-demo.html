02 Three harnesses, three different shapes

The same "opt-in LLM" idea, deliberately scoped differently per agent's actual stakes — never a copy-paste of the same pattern three times.

Documentation · 041

Authors content

Writes README / API-doc prose directly. Lowest stakes — output is read, not executed, and a bad result is just rejected, same as today.

Failure mode: fails the task closed. Never a silent fallback to the mechanical template.
DevOps · 042

Picks parameters

Decides parameters fed into existing, unmodified templates — never authors Dockerfile / CI‑YAML itself. Output is executed (docker build, a real pipeline), one stakes-level up.

Failure mode: fails the task closed. Same precedent, restated deliberately.
Security · 043

Adds commentary

No write path, no approval gate at all — so the model may only append additive commentary. Structurally unable to remove or downgrade a real finding.

Failure mode: stays completed with findings intact. A departure, reasoned through, not a copy of the other two.
